# Assemble Electrix interface system

Audience: a job-work factory supervisor checking materials and recording a shift, and an owner preparing customer bills.
Domain: customer challans, CKD assemblies, component requirements, accepted pieces, dispatch balances, piece rates.
Color world: dark blue machine panels, teal workshop markings, white inspection sheets, amber safety markers, steel gray.
Signature: a material-to-payment production flow showing real quantities at every gate; a BOM readiness sheet calculates the exact components needed before a production entry.
Avoid: decorative revenue charts, generic marketing hero sections, unrelated illustrations.

Palette: workshop navy #112c34; production teal #087f72; paper #f6f8f9; ink #18343c; steel #52696f; safety amber #a56813.
Typography: locally bundled Manrope, 13px module table text / 12px Overview body, 11–12px metadata, 17px module / 14px Overview section headings, 30px page headings (25px mobile), tabular numerals.
Layout: 232px navigation, left-aligned content, bounded tables, quiet borders, 32px desktop gutters. Existing desktop/tablet layout remains unchanged at 640px and above. Phones below 640px use a 56px compact header, 12px content gutters, and a fixed bottom navigation bar with safe-area padding. Demo notices and primary page actions start within 120px of the top.
The desktop sidebar stays within the viewport: the brand and company footer are fixed within the dark panel, and only the navigation list scrolls on shorter screens.
Controls: shadcn buttons are 36px default, 32px small, 40px large; entry fields are 40px. Mobile buttons and module/filter selects are at least 44px. Controls use 6px radii, Overview panels 6px, other module panels 10px. shadcn components for controls, dialogs, fields, badges, alerts, and empty states.
Motion: instant navigation and data changes; 200ms dialog opacity/transform; 120ms Overview color transitions. Reduced motion removes dialog/spinner animation and Overview transitions.
State: demo and actual records are separate databases. No invented real customer rates. Visible form validation, loading, empty states, persistent storage errors.

Overview: plain module title, date, user-entered shift; real attention alerts before unequal KPIs, with Pending QC and Unbilled emphasized. No KPI icons. Desktop due orders retain a 780px minimum width and eight rows per page. Below 640px alerts stack title/detail/right-aligned action, and due-soon/at-risk orders share one deduplicated row with due dates. Due orders use cards on phones. Last eight operational activities show quantities, customers, actors, and dates; unknown actors stay unknown. Material-to-billing distinguishes component pcs from product pcs and keeps the existing conversions; phone stages wrap into a two-column grid. Desktop conversion/activity columns retain their existing proportions.
Identity: supplied AE SVG mark, Assemble Electrix name, matching favicon; local Manrope Latin subset. Sidebar promo/tagline is removed. Overview has a global text search for jobs, customers, and products; each inner module has one register search and no duplicate header search. Module exports are formatted Excel workbooks.
Operational truth: low stock compares customer balances against outstanding production BOM requirements; QC aging uses createdAt over 24 hours; rejects today use recorded QC date. Shift/operator preferences are local and separate per demo/actual workspace; missing values are not inferred. Backup reminder tracks initiated JSON downloads only, with unknown history labeled Not recorded. The comparison clock updates to the same backup timestamp so Today appears immediately.

Overview polish: every attention row uses the same three columns (title, detail, action), including the stock disclosure. Small severity dots mark red issues before amber reminders. Rejections appear only in alerts. Cards use 12px desktop / 10px mobile insets with 6px radii; actions use short verbs. Refresh, Backup, and Restore backup use outlined secondary controls. Last-backup status is visible only for Actual records, with a small Backup link in the desktop sidebar.

Final Overview details: all four KPI cards have a bottom action and equal row heights; Produced today links to Production. Pending QC and Unbilled use #B45309 on #FFFBEB. Alert actions use a verb and arrow. The Shift control is a bordered 6px button with a dropdown indicator and opens the existing settings dialog.

Inner-page polish: titles have no gray subtitle or top-level breadcrumb. Card subtitles explain operating rules only. Each page has one solid green action; Products & BOM uses Export BOM · Excel. Row actions use small outlined buttons, including Receive more and Record production. Action buttons have no plus icons. Demo uses a slim one-line notice; repeated footer notes are removed. Production puts pending inspections first without changing saved order or quantities.

Phone controls: header contains the AE mark, current page title and More button. Bottom tabs are Overview, Production, QC, Dispatch and More. More is an accessible dialog styled as a bottom sheet; it contains other modules, global search, workspace selection, Refresh, Backup, Restore backup, date and shift. Opening the sheet focuses its heading so the keyboard stays closed, and dismissal restores the opening button's focus. Actual-only backup history stays inside More. All touch controls are at least 44px tall.

Phone registers: reuse the same table rows, pagination, values and existing action handlers. Each row becomes a labeled card with status pills where applicable and a full-width existing action at the bottom. Core registers do not scroll horizontally. Job references never wrap; customer names wrap at word boundaries. Rejection reasons stay inside their Production card. Native select focus is released after pointer choices only; keyboard focus remains visible.

Phone BOM: the product list occupies the full width and scrolls with the page. Tapping a product opens its detail and returns to the top. Products returns to the list; Export BOM is outlined on phones and keeps the existing desktop primary variant. The phone demo notice is exactly “Demo data · Use actual records →”.

Risk and recovery: Job orders and Overview share an At risk forecast using recent usable output over up to seven calendar days, including idle days. Accepted and pending pieces count toward the production target; known rejects do not. Risk appears as an amber pill on desktop and red (#B91C1C on #FEF2F2) on phones and in Needs attention without changing order status or saved records. Restore backup validates the selected snapshot, shows a confirmation before replacement, and remains available when records fail to load. Load errors say: "Couldn't read saved records in this browser. Try again or restore a backup."

Mobile More sheet: uses the dialog bottom placement without centering offsets or individual translate. Fixed left/right/bottom at zero, width 100%, maximum height 85dvh, internal vertical scrolling and safe-area bottom padding. Enter/exit animate translateY only and honor reduced motion. Six labeled icon links and Data controls form single-column lists, with full-width controls at least 44px tall. The portal sits directly under body; Radix locks body scroll. A temporary history entry makes browser Back dismiss the sheet; module/backdrop dismissal consumes that entry before any navigation. Phone landscape navigation is available up to 900px wide and 430px high. Tab labels are 11px. Verified at 320, 360, 375, 412, 430px and 844×390 landscape.
