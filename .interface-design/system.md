Audience: a job-work factory supervisor checking materials and recording a shift, and an owner preparing customer bills.
Domain: customer challans, CKD assemblies, component requirements, accepted pieces, dispatch balances, piece rates.
Color world: white billing registers, red action stamps, charcoal ledger text, gray workshop forms, amber safety markers and green accepted-piece labels. The current direction is Vyapar-inspired billing software adapted to job-work manufacturing.
Signature: a material-to-payment production flow showing real quantities at every gate; a BOM readiness sheet calculates the exact components needed before a production entry.
Avoid: decorative revenue charts, generic marketing hero sections, unrelated illustrations.

Palette: action red #c9263d; AE red #D92D42; canvas #f5f6f8; paper #fff; ink #243047; metadata #647084; borders #e0e4eb; selected navigation #fff0f2. Amber #b45309 on #fffbeb marks waiting; green #226342 marks accepted; red #b42318 marks problems. Semantic tokens live in src/factory-design.css.
Typography: locally bundled Manrope, 12px module table/body text, 10–11px metadata and table headings, 14px section headings, 25px page headings, tabular numerals. Module summaries use 22px totals on desktop and 18px on phones.
Layout: 224px light navigation (200px on tablets), grouped into Workspace, Manufacturing and Records & billing. Left-aligned content, 24px desktop gutters, compact white registers with gray headings. Phones below 640px retain a 56px header, 12px gutters and bottom tabs with safe-area padding. Demo notices and primary page actions start within 120px.
The desktop sidebar stays within the viewport: brand and company footer are fixed within the light panel, and only the grouped navigation list scrolls on shorter screens.
Controls: reuse shadcn buttons, dialogs, fields, badges, alerts and empty states. Buttons use 5px radii; panels use 6px; dialogs use 8px. Default buttons remain 36px, small 32px, fields 40px. Mobile controls remain at least 44px tall.
Motion: instant navigation and data changes; 200ms dialog opacity/transform; 120ms Overview color transitions. Reduced motion removes dialog/spinner animation and Overview transitions.
State: demo and actual records are separate databases. No invented real customer rates. Visible form validation, loading, empty states, persistent storage errors.

Overview: plain module title, date, user-entered shift; real attention alerts before unequal KPIs, with Pending QC and Unbilled emphasized. No KPI icons. Desktop due orders retain a 780px minimum width and eight rows per page. Below 640px alerts stack title/detail/right-aligned action, and due-soon/at-risk orders share one deduplicated row with due dates. Due orders use cards on phones. Last eight operational activities show quantities, customers, actors, and dates; unknown actors stay unknown. Material-to-billing distinguishes component pcs from product pcs and keeps the existing conversions; phone stages wrap into a two-column grid. Desktop conversion/activity columns retain their existing proportions.
Identity: supplied AE SVG mark, Assemble Electrix name, matching favicon; local Manrope Latin subset. Sidebar promo/tagline is removed. Overview has a global text search for jobs, customers, and products; each inner module has one register search and no duplicate header search. Module exports are formatted Excel workbooks.

Phone controls: header contains the AE mark, current page title and an ellipsis button for Data actions. Bottom tabs are Overview, Production, QC, Dispatch and More. All touch controls are at least 44px tall.

Phone registers: reuse the same table rows, pagination, values and existing action handlers. Each row becomes a labeled card with status pills where applicable and a full-width existing action at the bottom. Core registers do not scroll horizontally. Job references never wrap; customer names wrap at word boundaries. Rejection reasons stay inside their Production card. Phone BOM: the product list occupies the full width and scrolls with the page. Tapping a product opens its detail and returns to the top. Risk and recovery: Job orders and Overview share an At risk forecast using recent usable output over up to seven calendar days, including idle days. Risk appears as an amber pill on desktop and red (#B91C1C on #FEF2F2) on phones and in Needs attention without changing order status or saved records. Restore backup validates the selected snapshot, shows a confirmation before replacement, and remains available when records fail to load.
